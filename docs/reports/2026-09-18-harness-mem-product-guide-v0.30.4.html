02 / Quick start

同じコマンドで始めて、使うものを選ぶ

ターミナル（コマンドを入力する画面）に、そのまま貼り付けます。利用する道具に合わせてコマンドを書き換える必要はありません。

共通の導入コマンド
› npx -y --package @chachamaru127/harness-mem harness-mem setup

公開版と改善版の違い：現在の公開版v0.30.4でも、このコマンドから接続先を手動で選べます。以下の自動検出と最後の実行確認は、次版向けにローカル実装した導線です。まだnpmの公開版には含まれていません。

STEP 1 / 自動確認

利用環境を読み取る

言語を選ぶと、Codex、Claude Code、Cursorなどのコマンドや設定の有無を確認します。アプリは起動しません。
表示：コマンドあり / 設定あり / 未検出。見つかったことと、正常に接続できることは区別します。
STEP 2 / 選択

つなぐ道具を選ぶ

検出した主な対応環境を候補として表示します。候補のままでよければEnter。変える場合は画面の番号を選びます。
例：CodexとClaude Codeを使うなら 1,4。設定ファイルやコマンドの編集は不要です。
STEP 3 / 実行

内容を確認して導入

任意の移行と自動更新を選びます。接続先と変更内容を確認して y を入力すると、設定、サーバー起動、動作確認へ進みます。
中止：対象選択の q、入力終了、最後の確認の n では設定を変更しません。
選択画面の例を見る（次版向け）
1) codex        コマンドあり
2) cursor       未検出（使っている場合は選択可）
3) opencode     未検出 / 試験対応、手動選択
4) claude       コマンドあり
5) antigravity  未検出 / 試験対応、手動選択

推奨候補: codex,claude
候補がある場合はEnterで選択できます。
> [Enter]

（任意の移行と自動更新を選択）

接続先: codex,claude
この内容でインストールを実行しますか? [y/N]: y

候補が見つからなければ、利用する道具を自分で選びます。OpenCodeとAntigravityは試験対応のため自動選択に含めません。HermesとGrok Botは、それぞれの連携手順を使います。

あなたの仕事は、つなぐ道具を選び、導入後に会話を取り出せることを確かめることです。新しいセッション（ひと続きの会話）を開き、同じプロジェクトから確認します。

最初に残す内容の例

「このプロジェクトの次の作業は、認証後の権限テスト。確認用の目印は mem-guide-check」

新しい会話で尋ねる例

「このプロジェクトの mem-guide-check を記憶から探し、次の作業を教えて」

成功条件：保存した目印と作業内容が、同じプロジェクトから返る。
実行する前に必要なもの

Node.js / npm（配布パッケージを動かす道具）とBashが必要です。モデル取得にはネット接続と空き容量を使います。導入中はcurl、jq、Bun、ripgrepも必要となり、macOSではBunとripgrepの自動導入経路があります。不足をすべて自動解決する保証ではありません。

macOSとLinuxではターミナルで実行します。WindowsではGit BashまたはWSL2（Windows内でLinuxを動かす環境）を使います。PowerShell / CMDだけでは全体導入の前提を満たしません。

設定先は利用者のホーム配下です。sudoは付けません。端末で対話できない自動処理の場合だけ、実行担当が接続先を明示します。

導入後に、設定を変えずに診断する
npx -y --package @chachamaru127/harness-mem harness-mem doctor --read-only

設定済みの接続先を診断します。インストール済みでも、新しい会話で記録が取り出せるかは別に確認します。

AIが呼び出す記憶機能と、3つの自動処理

harness_mem_search は保存した記憶の検索、harness_mem_resume_pack は作業再開に使う情報の取得、harness_mem_record_checkpoint は途中経過の記録です。これらはMCP（AIが機能を呼び出す接続規格）を通じて使います。

Claude Code / Codex CLIの自動連携では、SessionStart が会話開始時、UserPromptSubmit が入力時、Stop が終了時の処理を担当します。会話の内容や接続状態によって、渡される記憶は変わります。

04 / Safety layer

保存範囲と外部接続を分けて考える

保護は、記憶への保存と読み出しにかかります。AIサービスへ送った元の会話や、利用端末全体を保護する仕組みとは区別します。

検索時に守るプロジェクト境界
strict_project: true / プロジェクトを限定

完全なプロジェクト識別子と strict_project: true を指定した検索は、その範囲に限定されます。同じ名前の別リポジトリを、名前だけで自動統合しません。

同じ案件を引くには、保存側と検索側の識別子を揃えます。
利用者が選ぶ外部処理
local by default / 追加経路は明示設定

無料のローカル経路は外部APIを必要としません。Proは外部の処理先とキーを設定する任意の経路です。外部LLM（文章を解釈するモデル）による事実抽出は、許可フラグと認証情報の両方が必要です。

秘密を保存対象から外す
<private>…</private> で囲んだ部分を、通常の記憶保存前に除去します。すべての秘密を自動検出する保証ではありません。任意の原文保持設定は別途確認します。
接続先は手元が既定
新規Claude / Codex設定は、手元の通信窓口と所有者だけが読める認証ファイルを使います。データベースの暗号化とは別の保護です。
診断と修復を分ける
doctor --read-only は設定変更やサービス起動をしません。--fix は修復操作です。調査時は目的に合うモードを選びます。

09 / FAQ

使い始める前の疑問

入れると、AI自体が賢くなる？

モデルの能力を再学習で変える機能ではありません。前回の判断や会話を検索し、今回の回答に使える材料を増やします。古い記録や誤った記録をどう扱うかは、根拠と現在の状態を見て判断します。

本当に無料で、外部へ何も送らない？

無料のローカル経路に、記憶処理用の外部APIキーは不要です。導入やモデル取得では通信します。Proや外部LLM抽出は任意設定です。記憶を受け取るClaude CodeやCodex側の通信とデータ利用は、それぞれのサービス設定に従います。

古い会話も全部、そのまま戻る？

保存または取り込み済みの内容が対象です。検索結果や再開時の情報は選別され、会話全文を毎回渡すものではありません。フックの接続、取り込み状況、検索用データの整備によって、戻せる範囲が変わります。

覚えさせたくないことがあるときは？

通常の保存経路では <private>…</private> を使って対象部分を除外できます。recall offは関連記憶の差し込みを止めるだけで、記録全体や開始時の再開機能を止める操作ではありません。利用する経路と保存設定を確認してください。

社内利用や商用アプリへの組込みはできる？

ライセンスはBUSL-1.1（利用条件を伴うソース公開ライセンス）です。LICENSEには社内利用、個人利用、独立した記憶サービスではない自社アプリへの組込みなどの許可が記載されています。第三者向けの商用マネージドMemory Serviceには制限があります。該当する使い方はLICENSE原文と照合してください。

10 / Glossary

しくみを読むための6語

プロジェクト識別子 = 記憶をどの開発案件に属させるかを示す値。
確認済みのルートフォルダを使い、表示名だけで同一視しません。
フック = 会話の開始や入力に合わせ、決まった処理を呼ぶ仕掛け。
接続が無効だと、自動記録や再開情報の受渡しも働きません。
MCP = AIクライアントが外部の機能を呼ぶための接続規格。
harness-memでは、記憶の検索や記録を呼び出します。
SQLite = 手元のファイルにデータを保管するデータベース。
1つのDB内でプロジェクトや会話を区別します。
ベクトル = 文章の意味の近さを比べるための数値データ。
言葉が完全一致しない検索を補います。作成処理を埋め込みと呼びます。
デーモン = 裏で動き続け、記録や検索を受け付けるサーバー。
harness-memdが、各クライアントからの依頼を処理します。
最初の到達点

1つのプロジェクトで目印付きの記録を残し、別の会話から取り出せたら、引継ぎの基本動作を確認できます。次の作業が今も正しいかを判断する役割は、人に残ります。

正直な但し書き
  • 自動再開には、対応クライアントのフック接続と正常なローカルサーバーが必要です。全クライアントでの同等動作は保証しません。
  • 旧来の短いプロジェクト名の記録は、完全なパスへ自動統合されません。別リポジトリを混ぜないため、対応関係の確認が必要です。
  • 補完対象の整備率100%は、全履歴の回収率や検索正答率100%を意味しません。速度は保存量、検索条件、端末の負荷で変わります。
  • 公開版0.30.4と、PR #180を含む開発中のmainは異なります。PR #180のNode 18検証結果を、公開版の新規導入保証には使っていません。
  • ローカル保存は、端末故障に対する保全やDB暗号化の保証ではありません。会社全体の文書共有、アクセス権管理、AIの作業承認を、この記憶機能だけで代替しません。
